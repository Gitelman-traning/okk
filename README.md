# ОКК — разбор встреч отдела продаж

Берёт расшифровки зум-встреч, считает измеримое кодом, остальное отдаёт языковой модели и складывает разбор в таблицу.

## Как устроено

Оценка идёт двумя слоями:

- **код** — счётчики обязательных формулировок, объём речи, количество вопросов. Здесь модель не участвует, ошибиться нечему;
- **модель** — то, что требует понимания смысла: достигнута ли цель встречи, что с потребностями и возражениями, каким получился следующий шаг. Каждый вывод обязан опираться на цитату из расшифровки; нет цитаты — критерий остаётся пустым, а не «выполненным».

Такое разделение отвечает на главный вопрос к подобным системам: чем больше объём, тем сильнее хочется доверять цифрам, поэтому цифры не должна выдумывать модель.

## Запуск

Workflow «ОКК — разбор диагностик», вручную, с лимитом встреч за прогон.

| Переменная | Что это |
|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter; модель выбирается автоматически из бесплатных с достаточным контекстом, либо задаётся полем `model` при запуске |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | сервис-аккаунт с доступом к таблице и папке расшифровок |
| `SHEET_ID` | таблица, где лежат ссылки на расшифровки и куда пишется разбор |
| `CHECKLIST_JSON` | чек-лист: контекст компании, обязательные и запрещённые формулировки |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | отбивка о прогоне, необязательно |

Ни идентификаторов, ни чек-листа в коде нет — репозиторий публичный, всё это приходит снаружи.
