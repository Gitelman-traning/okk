# ОКК на ИИ — правила для работы через Claude Code

Публичный репозиторий: код разбора диагностических встреч Второй линии. Здесь нет и не должно быть данных клиентов, чек-листов компании и ключей.
Приватные документы (чек-листы, оценки человека, расходы, ТЗ) — в `okk-docs`. Страницы результата живут в Штабе (`shtab/site/public/sales/l2/`).

## Что здесь
- `okk_analyze.py` — разбор по чек-листу (элементы «спросил / прозвучало» с цитатами), запись в лист «ОКК».
- `coach.py` — разбор по методике «Коуч по диагностикам» (100 баллов из семи блоков, светофор, статус сделки), лист «Коуч». Рубрика — `RUBRIC` в коде.
- `diarize.py` — Deepgram с разделением говорящих; `one_off.py` / `batch_off.py` — одна запись / пакет по листу ZOOM; `anonymize.py` — обезличивание перед отправкой модели.
- `build_dashboard.py` + `*.tpl.html` — сборка страниц из листов таблицы; `verdict.js` — формула вердикта.
- `.github/workflows/` — прогоны: `review`, `diarize`, `oneoff`, `batch`, `coach`, `models`. Все секреты — в GitHub Secrets.

## Правила
1. Всё, что уходит в модель, сначала обезличивается (`anonymize.py`). Ключи и содержание встреч в логи и в git не попадают.
2. Прогоны платные: перед тестом смотри, есть ли расшифровка в кэше (артефакт `transcript-<md5 клиента>`), запускай с `reuse`/кэшем.
   Модель по умолчанию для массовых прогонов — Sonnet 5, для эталонов и спорных — Opus. Расходы ведутся в `okk-docs/EXPENSES.md`.
3. Параметры моделей различаются: старые Claude принимают `thinking.type=disabled`, новые (5.5, Fable) — только `adaptive` + `output_config.effort`,
   OpenAI не знает `thinking`, требует `max_completion_tokens` и температуру по умолчанию. Смотри `extra_for()` в `coach.py`.
4. Новая проверка в чек-листе — через конфиг (`CHECKLIST_JSON` / `COACH_RUBRIC_JSON`), а не хардкод имён и цифр компании в коде.
5. Страницы собираются `build_dashboard.py` из листов таблицы; на сайт их кладёт `shtab/build.py`. Шаблон новой страницы — по образцу `coach.tpl.html`
   (стили `/ui.css`, меню `/nav.js`, данные подставляются в `/*__DATA__*/`).
6. Изменения — через pull request; владельцы — в `.github/CODEOWNERS`.
